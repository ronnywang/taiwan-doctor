# 鄉鎮猜猜樂

台灣版 GeoGuessr：隨機出一個鄉鎮市區名稱，玩家在地圖上點出位置，越近分數越高。

## 跑起來

```bash
python3 -m http.server 8787 --directory .
# 開 http://localhost:8787
```

（`data/towns.json` 用 fetch 載入，所以不能直接用 file:// 開。）

## 資料來源

歐噴資料庫（data.openfun.tw）／內政部社會經濟資料服務平台
資料集 `tw.openfun~entity~geo`，取 `level=town&_as_of=now` 的 368 個現行鄉鎮市區，
邊界由 GIS API `/api/v1/geo/shapes/` 取得。縣市輪廓由鄉鎮邊界合併而成，未另外下載。

### 資料處理（原始 33 MB → 550 KB）

| 處理 | 說明 |
|---|---|
| 簡化 | Douglas–Peucker，tolerance 0.001 度（約 110 公尺） |
| 去小島 | 每個鄉鎮保留最大的一塊，其餘只留面積 ≥ 0.2 km² 者 |
| 去東沙 | 高雄市旗津區的東沙群島（116.7°E）會把地圖拉爛，排除 |
| 去釣魚臺 | 宜蘭縣頭城鎮的釣魚臺列嶼（123.5°E）、基隆市中正區的彭佳嶼，同理排除 |

結果：368 鄉鎮、400 個 polygon、27,713 個座標點。

另外產出 **22 個縣市的輪廓**（62 塊、8,349 點），畫成比鄉鎮界明顯的粗線，方便辨識縣市範圍。
縣市輪廓是用**未簡化**的鄉鎮多邊形先 dissolve 再簡化——若拿簡化後的鄉鎮去合併，
相鄰鄉鎮的邊界會對不齊而產生縫隙與碎片。
每個鄉鎮都有一個保證落在自己範圍內的代表點（shapely `representative_point`）。

## 地圖分區

金門與馬祖離本島太遠，直接畫會讓本島被壓到很小，所以切成三塊：

| 區塊 | 範圍 | 畫在哪 |
|---|---|---|
| `main` | 119.2–122.4°E, 21.8–25.45°N（本島＋澎湖＋蘭嶼＋綠島） | 主地圖 |
| `kinmen` | 118.05–118.65°E, 24.3–24.65°N | 左上角小框 |
| `matsu` | 119.85–120.55°E, 25.9–26.45°N | 左側小框 |

**計分一律用真實經緯度**，不受分區影響——答案是金門時，點在本島會吃到約 300 公里的距離懲罰。
金門縣金湖鎮的烏坵（119.45°E）落在 main 範圍內，所以它會畫在主地圖的海上，位置是對的。

螢幕上小於 6px 的島嶼會額外補一個圓點，否則馬祖和澎湖的小島看不見也點不到。

### 圖層順序

`鄉鎮填色 → 答案highlight → 縣市輪廓 → 作答標記與連線`

縣市輪廓畫在答案之上，所以答對時仍看得出它落在哪個縣市；
作答標記與連線畫在最上層，不會被任何東西蓋住。

## 兩種模式

### 距離模式（預設）

5 題，隨機出鄉鎮名，點地圖，依距離計分。詳見下方「計分」。

### 占領模式

選一個縣市或全國，出鄉鎮名，**點中才算**（不看距離）。
點對就把該鄉鎮「占領」變綠，直到全部占完。

| 規則 | 說明 |
|---|---|
| 點對 | 占領該鄉鎮（變綠），本題試錯的紅色一併清掉，換下一題 |
| 點錯 | 答錯 +1，**該鄉鎮標紅**留在畫面上，可用刪去法繼續試 |
| 再點同一個紅的 | 不重複計錯 |
| 點到海上 | 不罰、不計 |
| 點已占領的 | 不罰、不計 |
| 同名鄉鎮 | 只要是**範圍內、同名、未占領**的就算對；點到範圍外的同名鄉鎮算錯 |

**單人不冷卻**（`COOLDOWN_SOLO = 0`）——試錯標紅本身就是進度，不需要再罰時間，
這樣每一局都保證能全破。連線版才啟用 `COOLDOWN_MP = 2000`，
因為競速時若無懲罰，最佳策略會退化成亂點掃過去。

### 縣市鎖定

選單選了特定縣市時，地圖會**自動縮放到該縣市並鎖住範圍**：
縮小的下限就是該縣市剛好塞滿畫面，平移也不能移出該縣市的外接矩形。
倍率顯示會變成相對值並標註「鎖定○○縣」。

實作是把 `view` 加上 `rect`（底圖座標的可視矩形）與 `kmin`，
全國模式的 `rect` 就是整張畫布、`kmin = 1`，兩者走同一套 clamp 邏輯。
金門、馬祖在離島小框裡，一樣能正確鎖定（小框區域就是它們的 rect）。

**難度會自己遞減**：占領過的變綠被排除，剩下的選項越來越少，後段用刪去法就能加速。
最後幾個幾乎是送分，這是刻意保留的收尾爽感。

各縣市鄉鎮數差很多，選單會標出來：高雄市 38、臺南市 37、屏東縣 33⋯⋯
最小的嘉義市只有 2 個、新竹市 3 個，單獨玩幾秒就結束。

出題順序用 **seeded PRNG（mulberry32）** 產生，同一個 seed 的順序完全一致——
這是為連線版準備的：同房同 seed，所有人看到的題目順序就會相同，不需要伺服器發題。

## 計分

- 點在正確鄉鎮範圍內 → **1000 分**
- 否則 `score = 1000 × exp(−d / 50)`，d 是點到該鄉鎮邊界的最短距離（公里）

| 距離 | 5km | 10km | 25km | 50km | 100km | 200km |
|---|---|---|---|---|---|---|
| 分數 | 905 | 819 | 607 | 368 | 135 | 18 |

調整 `index.html` 的 `SCALE`（預設 50）可以改衰減速度，`ROUNDS`（預設 5）改題數。

## 同名鄉鎮

368 個鄉鎮裡有 8 組同名、共 19 個：

| 名稱 | 縣市 |
|---|---|
| 東區 | 嘉義市、新竹市、臺中市、臺南市 |
| 北區 | 新竹市、臺中市、臺南市 |
| 中正區 | 基隆市、臺北市 |
| 中山區 | 基隆市、臺北市 |
| 信義區 | 基隆市、臺北市 |
| 西區 | 嘉義市、臺中市 |
| 大安區 | 臺北市、臺中市 |
| 南區 | 臺中市、臺南市 |

**目前作法：點中任一個都算，取最近的那個計分。** 題目只提示「全台有 N 個同名鄉鎮」，
**不列出是哪些縣市**——列出來等於把答案範圍縮小到那幾個縣市，難度會掉太多。
因為題目只給「中正區」時本來就無法判斷是哪一個，要求指定特定一個並不公平。

另有 11 組「去掉區/鄉/鎮/市後同名」的（信義鄉 vs 信義區、大同鄉 vs 大同區、
東勢鄉 vs 東勢區、仁愛鄉 vs 仁愛區等），因為全名不同，視為不同題目。

## 畫面與縮放

版面固定 100vh、頁面不捲動（手機寬度 <860px 例外，改為上下堆疊並允許捲動）。

地圖支援滾輪縮放、拖曳平移、雙指縮放，倍率 1×–40×，右下角有 ＋／－／⟲ 按鈕。
滾輪一格約 1.57×，＋／－ 按鈕每次 2.2×。
整個 `#viewport` group 套一個 `translate + scale`，所以三個分區（本島、金門、馬祖）一起縮放，
不需要各自維護一套變換。

- 點擊座標用 `svg.getScreenCTM().inverse()` 轉成 viewBox 座標後，再還原 viewport transform，
  因此**縮放不影響作答精度**（實測還原誤差為 0）。
- 拖曳超過 4px 視為平移，不會誤判成作答。
- 線條都用 `vector-effect:non-scaling-stroke`，作答標記半徑設 `6/k`、
  離島小框標籤字級設 `13/k`，所以放大時它們維持固定視覺大小。
- 小島補的圓點**刻意不做反向縮放**，放大時會跟著島一起變大，剛好蓋在真正的島形上。

### 滑過highlight

滑鼠移到鄉鎮上會把**整個鄉鎮**（含它所有離島，例如澎湖縣白沙鄉有 6 塊）打亮，
點下去前先確認點到的是哪一個。**只打亮形狀，不顯示名稱**——顯示名稱等於直接送答案。

實作上答案層、連線層、標記層、離島小框都設 `pointer-events:none`，
hover 事件才打得到底下的鄉鎮 path；拖曳平移中不觸發 highlight。

### 為什麼需要縮放

不是為了分數——主地圖 1px ≈ 0.55 公里，而計分是 `exp(-d/50)`，差 1px 只掉 1%。
真正的理由是 **🎯 完美命中**與**城鄉公平**：

| | 面積 | 1× 螢幕大小 | 10× |
|---|---|---|---|
| 花蓮縣秀林鄉 | 1,642 km² | 很大，隨便點都 🎯 | — |
| 臺北市中正區 | 7.6 km² | 約 10px | 約 100px |

地圖上沒有任何地名標籤，所以放大只會讓手更穩，不會洩漏答案。

## 設定

- **排除離島**：題庫去掉金門、馬祖、澎湖、蘭嶼、綠島（357 組 → 339 組）
- **題目顯示縣市**：簡單模式，直接給「臺北市中正區」

## 連線版的既有調查（尚未實作）

用使用者自架的 chatroom 服務：`wss://chatroom.openfun.app/ws`（[API.md](https://chatroom.openfun.app/API.md)）。

**已實測可行：** 從瀏覽器連 WS 187ms 建立連線，`join` → `joined`、
`say` → 原樣廣播回來並附**伺服器端 timestamp**。

| 問題 | 解法 |
|---|---|
| 誰先點到？ | 單一伺服器單一房間，**廣播順序對所有人一致**，各自取「第一個有效 claim」即可，不需要主機仲裁（主機仲裁會讓房主有零延遲優勢，不公平） |
| 題目順序同步 | 占領模式已用 seeded PRNG（mulberry32），開房時把 seed 放進第一則 `say`，所有人各自算出相同題序 |
| 斷線重連 | **不處理**——有人斷線就中止比賽（使用者決定，2026-10-18） |

**已知限制：**

1. `history` 只留最後 100 則 `say`。全國模式 368 次占領會超過，中途加入者會漏掉早期狀態；縣市模式（最多 38）沒問題。
2. **REST API 沒有 CORS 標頭**（實測 `/api/health` 回 200 但無 `Access-Control-Allow-Origin`），
   所以瀏覽器無法用 `/api/rooms` 做房間列表。要嘛全部走 WS，要嘛在伺服器加一行 CORS。
3. 資料全在記憶體，伺服器重啟清空，不能做長期排行榜。
